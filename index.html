01
세 층의 정체와 경계
경쟁 관계가 아니라 한 파이프라인의 세 층입니다. 온톨로지 = T-Box(타입·계약), 지식그래프 = A-Box(인스턴스), GraphRAG = 질의·생성 런타임.
LAYER 1 · 계약

온톨로지 = 설계도

"무엇이 존재할 수 있고, 어떻게 연결되며, 무엇이 필수인가"를 기계가 읽을 수 있는 형태로 정한 계약입니다. 데이터 자체는 담지 않습니다.

담는 것 · 클래스, 관계와 도메인/레인지, 식별자, 제약(필수·카디널리티), 용어집, 출처 규칙

표준 · W3C OWL 2는 "클래스·속성·개체·데이터값"을 갖는 온톨로지 언어이며 형식적 의미를 정의합니다 · W3C SHACL은 그래프가 형태(shapes) 제약을 만족하는지 검증하는 언어입니다
LAYER 2 · 사실

지식그래프 = 서가

계약을 통과한 실제 사실(노드·엣지)만 저장합니다. 제안(초안)과 운영(승인된 사실)을 분리해 두는 것이 핵심입니다.

담는 것 · 노드·엣지 + 출처(어디서 왔는가) + 시점(언제 알았는가·언제부터 유효한가) + 신뢰 등급

표준 · W3C PROV-O는 출처 정보를 교환하기 위한 온톨로지입니다 · 제품 · Palantir Foundry 문서에는 "Review ontology proposals", "Ontology branches"처럼 제안 검토·분기 절차가 제품 기능으로 문서화되어 있습니다
LAYER 3 · 런타임

GraphRAG = 사서

질문을 받아 그래프와 원문에서 근거를 모으고, 근거 밖으로 나가지 못하게 묶어 답합니다. 전역(요약형) 질문과 국소(사실형) 질문을 함께 다룹니다.

담는 것 · 문서 조각(청크), 그래프 확장 경로, 인용·수치 검증 규칙, 커뮤니티 요약

연구 · Microsoft GraphRAG는 LLM으로 엔티티·관계·주장을 추출하고 커뮤니티 요약을 만들어 전역 질문에 답합니다 · 제품 · Neo4j GraphRAG, AWS graphrag-toolkit 등 1st-party 구현이 공개되어 있습니다
02
관계도 — 본류 1개 + 보조 2개
굵은 실선이 본류(설계 → 그래프 구현 → 근거 검색 → 답변)입니다. 온톨로지에서 GraphRAG로 가는 점선은 데이터가 아니라 규칙이 흐릅니다.
그림 1. 데이터 흐름(굵은 실선) · 규칙·스키마 제약(파랑 점선) · 환류(청록 순환 점선)
03
자기 강화 루프 — 회차를 거듭할수록 설계가 강해지는 원리
환류는 한 번 되돌아오는 화살표가 아닙니다. 매 회차의 성공과 실패가 다음 회차의 스키마·추출 규칙·검색 품질을 바꾸는 누적 학습 고리입니다.
그림 2. 회차 n의 처리 결과(보상·벌점)가 회차 n+1의 온톨로지·추출 규칙·검색으로 되돌아가는 자기 강화 루프
보상 신호 · 검증 통과 → 승격
성공한 클래스·관계 매핑이 다음 회차 추출의 정답 예시로 굳습니다.
벤치마크 · Microsoft GraphRAG의 Auto Prompt Tuning은 도메인에 맞는 추출 프롬프트를 자동 생성합니다
벌점 신호 · 미매핑·미해결 관계·출처 누락
버려지지 않고 스키마 변경 제안·추출 규칙 개선 후보로 축적됩니다.
벤치마크 · Palantir Foundry의 "Review ontology proposals"(온톨로지 제안 검토) 절차
망각 방지 · 계약을 테스트로 고정
회차가 늘어도 검증 규칙이 흐려지지 않게 제약을 자동 검사로 붙잡습니다.
벤치마크 · W3C SHACL(형태 제약 검증) · OWL 2(형식적 의미)
비교 가능성 · 같은 입력 → 같은 결과
입력·릴리스·매핑 버전을 고정하면 회차 간 비교(“강해졌는가”)가 성립합니다.
벤치마크 · 릴리스·매핑 버전을 그래프 산출물에 함께 기록하는 관행(온톨로지 거버넌스)
사람이 닫는 고리 · 의미와 책임
자동화가 끝까지 닫지 못하는 부분은 의미 확정과 승인입니다. AI는 초안·검증 보조까지, 최종 판단은 도메인 전문가가 서명합니다.

04
AI가 설계하고, 도메인 전문가가 검증한다
과거에는 전문가가 온톨로지를 손으로 작성했습니다. 지금은 AI가 문서·DB·로그에서 초안을 자동 생성하고, 전문가는 의미와 업무 규칙을 검증·승인하는 분업이 성립합니다.
그림 3. AI 자동 초안 → 기계 검증 → 전문가 검증(주황) → 릴리스 → 운영 반영 → 다시 AI 학습 신호로
1
소스 수집
문서·DB 스키마·로그·API를 권리·보안 등급과 함께 등록
2
AI 초안 생성
클래스·관계·제약·동의어 후보를 대량 추출(LLM·규칙 파서 결합)
3
기계 검증
형식·중복·도메인/레인지·SHACL 제약 자동 검사
4
전문가 검증
의미·경계·업무 규칙·법규·예외를 판단하고 승인/수정/반려
5
릴리스·반영
불변 버전으로 고정, 운영 그래프·검색에 반영, 이력 보존

역할 분담 — 자동화와 책임의 경계

AI(자동)가 잘하는 것도메인 전문가가 반드시 하는 것
대량 문서에서 후보 클래스·관계 추출개념의 의미·경계 확정(다의어·동의어 판정)
이름·정의·매핑 초안 제시업무 규칙·법규·회계·안전 기준의 타당성 판단
형식 오류·중복·도메인 위반 자동 점검예외와 우선순위 결정, 책임 소재 확정
유사 개념·변경 영향 범위 탐색승인 여부 결정(책임 있는 서명)

검증 게이트 최소 요건 5가지

  • 작성자 ≠ 승인자 · AI가 만든 초안을 AI가 승인하지 않는다(교차 확인)
  • 모든 사실에 출처 · 원문 위치·버전·해시까지 연결한다(PROV-O 계열)
  • 미승인은 사용 금지 · 제안 평면과 운영 평면을 분리한다
  • 릴리스 불변·되돌리기 · 과거 릴리스는 고치지 않고 새 버전으로만 바꾼다
  • 감사 이력 · 누가·언제·무엇을·왜 승인/반려했는지 남긴다
주의 · “AI가 온톨로지를 자동 설계한다”는 말은 초안 생성의 자동화를 뜻합니다. 승인까지 자동화하면 잘못된 개념이 그래프·검색·의사결정 전체로 전파됩니다. 사람 검증 게이트를 우회하는 자동 승격은 도입하지 않는 것이 안전합니다.

06
셋이 붙을 때 생기는 시너지 8
"효과가 좋아진다"는 주장이 아니라, 어느 장치가 그 효과를 만드는지까지 적었습니다.
시너지만들어지는 방식그 효과를 만드는 장치
① 환각 억제스키마 검증 × 인용 검증 × 운영 엣지만 확장 — 3중 게이트SHACL 형태 검사 · 인용 필수 · 그래프 확장 제한
② 재현성·감사같은 입력·같은 릴리스면 같은 결과, 승인 이력은 추가만 가능결정론적 처리·해시 · append-only 감사 로그
③ 시점 정합성공개 시점·유효기간을 지켜 미래 정보 사용을 차단available_at · valid_from/valid_to · 시점 필터
④ 설명가능성답변 → 문서 조각 → 출처 → 원문 위치까지 역추적청크 해시 · PROV-O 계열 출처 필드
⑤ 지식 복리 성장문서가 늘면 근거가 늘고, 매핑 실패가 스키마 제안으로 축적스키마 변경 제안 큐 · 릴리스 버전 관리
⑥ 오염 차단(거버넌스)작성자 ≠ 승인자, 제안 평면과 운영 평면 분리교차 검증 · 제안/운영 저장소 분리
⑦ 비용 통제사실 확정은 규칙·검증기가 담당, LLM은 해석·요약에 집중결정론 파서 · 수치 가드
⑧ 자기 강화(회차 축적)회차의 성공·실패가 스키마 제안·추출 프롬프트·매핑 정답으로 누적보상/벌점 신호 기록 · 자동 프롬프트 조정 · 회차 지표 비교
전역 질문과 국소 질문 · 그래프가 없으면 “이 데이터셋의 주요 주제는?” 같은 전역(요약형) 질문에 약합니다. Microsoft GraphRAG는 엔티티 그래프와 커뮤니티 요약을 미리 만들어 이 문제를 다루고, 약 100만 토큰 규모 데이터셋의 전역 질문에서 기존 RAG 대비 개선을 보고했습니다(논문 초록 기준). KAG는 반대로 수치·시간·전문 규칙처럼 논리·제약이 중요한 질문에서 벡터 유사도만으로는 부족하다는 문제를 제기하고 그래프+스키마 제약 결합을 제안합니다.

08
도입 판단 기준과 흔한 실패
기술 선택보다 순서가 결과를 좌우합니다. 아래 최소 단계를 건너뛰면 그래프는 만들어져도 쓰이지 않습니다.

최소 성숙 단계 (권장 순서)

  • 1. 질문·결정 목록 · 무엇을 판단하려는지 먼저 적는다(그래프는 수단)
  • 2. 용어집 + 최소 스키마 · 핵심 클래스·관계만으로 시작(과설계 금지)
  • 3. 출처·시점 연결 · 모든 사실에 “어디서·언제 알았는가”를 붙인다
  • 4. 검증 게이트 · 기계 검증 + 전문가 검증을 통과한 것만 운영 반영
  • 5. 지표 고정 · 미매핑률·반려율·인용률을 회차마다 기록해 비교한다

흔한 실패 패턴

  • 과설계 · 완벽한 온톨로지를 먼저 만들다 데이터 연결이 늦어져 프로젝트가 멈춘다
  • 스키마 없는 자동 추출 · 타입 없는 삼중항이 쌓여 검증·추론이 불가능해진다
  • 검증 없는 자동 승격 · 잘못된 개념이 그래프·검색·의사결정 전체로 전파된다
  • 시점 무시 · 미래 정보가 섞여 분석 결과가 실제보다 좋아 보인다(백테스트 착시)
  • 지표 없음 · “좋아졌다”를 증명하지 못해 확장 근거를 잃는다
요약 · 온톨로지가 무엇을 사실로 인정할지를 정하고, 지식그래프가 그 사실을 축적하며, GraphRAG가 그 사실을 근거로만 말하게 합니다. 여기에 AI의 초안 생성과 전문가의 검증이 결합하면, 회차를 거듭할수록 스키마·추출·검색이 함께 강해지는 자기 강화 구조가 됩니다.
